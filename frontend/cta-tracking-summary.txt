Tracking OptiTAB (cta_click + nav_click)

Objectif
- Standardiser le tracking des CTA business via un seul event "cta_click"
- Standardiser le tracking de navigation (menu/logo) via un event séparé "nav_click"
- Paramètres envoyés:
  - cta_click: cta_name, cta_location (+ app_user_id si disponible)
  - nav_click: nav_name, nav_location (+ app_user_id si disponible)

Implémentation globale (SPA incluse)
- frontend/src/services/analytics.js: initCtaTracking() écoute click + touch/pointer (capture)
  - Priorité 1: nav_click via closest('[data-track="nav"]')
  - Priorité 2: cta_click via closest('[data-cta-name]')
- Push dataLayer nav_click: { event: 'nav_click', nav_name, nav_location, app_user_id? }
- Push dataLayer cta_click: { event: 'cta_click', cta_name, cta_location, app_user_id? }
- Garde: si name ou location est vide -> on ne push pas d'event (pas de fallback "unknown")
- Protection anti-doublon: init unique + handler stocké sur window (remplacé en dev/HMR). Pas de dédup "fonctionnelle" des clics; on ignore seulement le click qui suit un touch pour éviter un doublon.
- frontend/src/main.js: initCtaTracking() appelé au démarrage

Anti double comptage (GTM) - IMPORTANT
- Vérifiez dans votre container GTM qu'il n'existe pas d'ancien tag "clic WhatsApp" / "clic bouton" qui envoie aussi un event GA4 sur les mêmes clics.
- Reco: ne garder qu'un seul flux (ex: 1 tag GA4 qui se déclenche uniquement quand event == "cta_click" / "nav_click").

User-ID / PII (IMPORTANT)
- Ne jamais envoyer email/téléphone dans la dataLayer.
- Dans le code: on n'envoie plus `user_id`; on utilise `app_user_id` (id interne non sensible) si disponible.
- Pour un vrai GA4 User-ID: mappez `app_user_id` vers le champ GA4 `user_id` au niveau du tag de configuration (via GTM), pas comme simple paramètre d'event.
